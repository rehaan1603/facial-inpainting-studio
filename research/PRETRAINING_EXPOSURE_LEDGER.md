# Pretraining exposure ledger

Updated 12 September 2026 to include the reference-assisted baseline and OSOR. This ledger separates checkpoint provenance from evidence of evaluation-set independence. A known checkpoint hash or an identity-disjoint project split does not establish that pretrained components have never seen the evaluation images.

The original LaMa repository distinguishes the Big-LaMa Places release from additional Places and CelebA-HQ checkpoints. That supports the intended source family, not a complete audit of our third-party export. [Original LaMa release instructions](https://github.com/advimman/lama#inference).

ResShift provides a face-inpainting application and a face-specific configuration. Our stronger FFHQ-path evidence comes from the pinned local configuration, rather than an assumption from the model name. [Official ResShift repository](https://github.com/zsyOAOA/ResShift), [pinned face configuration](https://github.com/zsyOAOA/ResShift/blob/bb03b7d21614cace01787e097c8a6ab6b945227d/configs/inpaint_lama256_face.yaml).

LPIPS adds learned calibration to classification-network features and provides the BAPPS perceptual dataset. Its documentation requires identifying the metric version; it does not establish that our face-evaluation images are absent from all pretraining. [Official LPIPS documentation](https://github.com/richzhang/PerceptualSimilarity).

The SDXL release identifies its inpainting adaptation and base lineage, but this is not an evaluation-membership audit. [SDXL inpainting model card](https://huggingface.co/diffusers/stable-diffusion-xl-1.0-inpainting-0.1). FaceID Portrait already accepts multiple photographs and has research-use restrictions. [FaceID model card](https://huggingface.co/h94/IP-Adapter-FaceID). InsightFace distinguishes MIT-licensed library code from noncommercial research pretrained models. [InsightFace library and model terms](https://github.com/deepinsight/insightface/tree/master/python-package). See DATA_AND_LICENSES.md for the local artifact boundary.

The reference demonstration uses validation identities and distinct source hashes. It is not an untouched final test, and distinct files do not prove separate capture events or absence of transformed duplicates. A fresh reference-assisted protocol must prevent target copies, shared identities across partitions, and clean-target information reaching inference. REFERENCE_METHOD_AUDIT.md defines these controls.

## Requirements before independence claims

1. Obtain authoritative training manifests where available and compare photographs, including transformed copies, against evaluation data.
2. For unresolved membership, retain the limitation and evaluate on an independently sourced external set with documented provenance. A different dataset name alone is insufficient.
3. Do not use test-set results to choose new controls or retrain the method. Integrity inspection may read test images, but must not become model selection.
4. Separate absence of exact/near-duplicate photographs from absence of shared identities. The current perceptual-hash audit is not an identity-recognition audit.

No external messages have been sent to checkpoint authors. No complete pretraining-independence claim is currently supported.
