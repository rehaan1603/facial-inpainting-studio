# Audit of reference-assisted facial inpainting

Checked 11 September 2026. Scope: a damaged target photograph, a supplied missing-region mask, and three or four other photographs supplied as showing the same person. This is a new research protocol alongside the earlier single-image study. This document records a literature audit and proposed experiments; it does not report reference-assisted experimental performance or establish novelty.

Adding several reference photographs is a useful product feature, but is already an established research approach. The defensible next step is to reproduce a working reference baseline, measure its actual failure modes, and test a narrowly defined contribution against the closest methods. A working website, a downloaded adapter, and an attractive example do not establish a publishable advance. Acceptance remains a peer-review decision.

Search visibility or an accessible abstract alone does not establish reproducibility or comparability.

## A precise candidate to investigate

The candidate is **selective reference use when both the supplied mask and the reference set are unreliable**. Its distinction would have to come from a verified mechanism and measured behavior in this joint setting. Reference aggregation, spatial gates, identity losses, mask prediction, and low GPU memory consumption separately do not establish originality.

Write the inference contract as `f(observed_target, supplied_mask, references, seed)`. The clean target, true occlusion mask, clean target parsing map, clean target landmarks, and target identity embedding must be unavailable to inference. Let each spatial reference weight depend only on permitted observations, predicted visibility, reference quality, and cross-reference agreement. Include an explicit reference-off path. A model can learn that insufficient evidence should reduce conditioning; it cannot infer certainty from an absent face.

Three falsifiable hypotheses are worth separating:

1. **Joint uncertainty hypothesis.** A selector trained on independently varied mask errors and reference degradation improves reconstruction under their combination beyond a reference selector and mask refiner trained independently. Test the full interaction, not only a favorable aggregate or one difficult example.
2. **Target-evidence hypothesis.** Conditioning a selector on trustworthy visible target evidence reduces inappropriate detail transfer compared with reference-only quality weights, reference consensus, and a global identity similarity score. Under a whole-face mask, this evidence is unavailable; the system must not claim to validate which identity is correct.
3. **Selective-output hypothesis.** A failure score calibrated on separate development identities can identify cases where reference guidance harms the result. Evaluate risk versus coverage and compare with simple reference rejection and no-reference fallback. Sampling disagreement alone is not a calibrated probability of correctness.

These are proposed experiments, not implemented contributions in this audit. A null result should be retained. If a close existing method already implements the same mechanism, narrow the project to a useful reproducible robustness benchmark or choose a demonstrably different mechanism before training. Do not rename existing adapter code and present it as a new model.

## Required comparisons and ablations

| Comparison | Keep fixed | What it resolves |
|---|---|---|
| Same SDXL inpainting backbone with reference conditioning off versus on | Checkpoint, mask, resolution, sampler, steps, text, seed, compositing | Whether reference information itself helps, without changing the generator |
| One, two, three, four references; five where protocol permits | Same eligible identities and nested reference sets | Benefit of extra distinct photographs; avoid changing the sample population with reference count |
| Repeat one photograph four times versus four distinct photographs | Conditioning strength and token/compute accounting | Whether improvement comes from information diversity or changed conditioning magnitude |
| Uniform aggregation, random single reference, fixed quality-selected reference, quality weights, consensus weights, proposed selector | Same images, frozen base, tuning budget | Whether complexity beats transparent controls |
| Global versus spatial weights; reference-only versus target-aware weights | Parameter budget and training examples where possible | Whether spatial and target-dependent components contribute |
| Mask refiner only, reference selector only, both, and joint training | Training updates, data exposures, seeds | Whether the claimed joint contribution exceeds independently added components |
| Exact masks, under-masks, over-masks, shifted masks | True missing area, facial location, corruption texture | Whether performance depends on mask accuracy and whether visible pixels are unnecessarily changed |
| Clean references, blur/JPEG/downsampling, pose/expression mismatch, one mismatched-person reference, all unusable references | Reference count and predetermined corruption schedule | Robustness and harmful information transfer; corrupted sets must not silently disappear from reporting |
| Raw output versus shared outside-mask compositing | Same generator prediction | Whether visible preservation is produced by the model or guaranteed by paste-back |
| Proposed failure scoring versus simple quality threshold and unconditional fallback | Same accepted fraction or disclosed coverage | Whether selective output improves reliability beyond dropping hard examples |

PVA is the direct published face-inpainting comparison. Include its released model/settings when feasible and report adaptation cost separately. ReSem-Face is a close recent architecture to audit and reproduce if usable code/weights are available; this audit has not verified a runnable release. RefSTAR and Ada-RefSR are particularly relevant to selector claims. LaMa and ResShift remain useful no-reference controls, but outperforming them with additional personal photographs does not isolate algorithmic improvement.

Give each method the same references when its interface permits. For fixed-reference-count methods, report a separate standard-protocol comparison instead of padding secretly or discarding cases. For methods requiring per-person tuning, train only on allowed references and charge the tuning time and memory. Report unavailable reproductions and failed settings. Never paste scores from different published datasets, resolutions, masks, or samplers into a table of local measurements.

## Data construction and leakage controls

The earlier 96-identity development protocol and the already observed object-composite test were single-image experiments. They do not become a new reference-assisted test by attaching photographs. They may supply engineering or development cases, with that status explicit. Freeze a new target/reference manifest and reserve fresh identities for a final evaluation before using its outcomes to choose the new method.

1. **Split identities before forming tuples.** Train, tuning, calibration, and final test identities must be disjoint. Build each target and its references entirely within its identity partition. Track any cross-source identity overlap. Existing CelebA labels and near-duplicate checks are useful evidence, not proof of real-world identity independence.
2. **Exclude target copies.** References cannot contain the clean target, its crop, mirror, resized/recompressed version, or another extraction of the same photograph. Audit exact hashes and transformed near-duplicates before selection. Where practical, separate burst/event frames and report the remaining similarity distribution.
3. **Use authoritative mappings.** Join CelebA-HQ filenames to original CelebA identity annotations through the provided HQ mapping; retain join counts and missing/ambiguous rows. The current LaPa records do not establish same-person reference groups, so do not invent them using visual resemblance. New grouping needs justified labels and validation.
4. **Predetermine reference selection.** Choose references using a fixed rule and allowed metadata before scoring reconstructions. Do not choose the reference set, prompt, mask expansion, or seed that most resembles the clean target. If selection uses a masked target embedding, prove it receives only the damaged input.
5. **Keep scoring data isolated.** Clean target RGB and the true mask are permitted for supervised training and evaluation scoring, not inference. Test this at the loader/API boundary. A perfect reference, true-mask run, or clean-target condition is an oracle diagnostic only and must not enter the main comparison.
6. **Audit every pretrained component.** Extend the existing exposure ledger to the diffusion base, VAE, adapter, reference face encoder, detector, parser, and identity evaluator. Include revisions and checksums. Disjoint local identity labels do not prove absence from their pretraining. State unresolved exposure instead of assuming it away.
7. **Preserve reference independence in uncertainty estimates.** Use identity as the resampling unit, not pixels, masks, or output seeds. Images sharing identity/references are correlated. Report identity count separately from total reconstruction count.
8. **Retain realistic and synthetic strata.** Synthetic occlusion provides target truth. Real damaged photographs usually do not; evaluate those separately without inventing PSNR/SSIM targets. Reference photos may differ in expression, age, lighting, or transient details even when they show the same person.

The original [ReF-LDM paper](https://arxiv.org/html/2412.05043v1) explicitly screens overly similar target/reference pairs and checks reference identity. That precedent reinforces why target-copy leakage is a material issue. Reusing its thresholds on another encoder or dataset requires separate justification.

## Measurements and decision rules

Report hole-region reconstruction error, whole-image LPIPS, visible-region change, boundary artifacts, and geometric consistency together. Add identity similarity with at least one permitted evaluator distinct from the conditioning encoder, identify both training sources, and report face-detection failures rather than excluding them. An independent evaluator reduces circularity but does not establish unknown pretraining independence. Reference similarity alone can reward copying the wrong expression or transient appearance.

Use paired identity-level intervals and repeated fixed seeds for stochastic inference. Predeclare primary contrasts and acceptable visible-change/noninferiority margins on development data; do not choose them after seeing final test performance. Treat small-sample FID as descriptive at most, not decisive evidence. Show all predefined mask/reference strata, failures, and inference costs, including cold loading, per-person adaptation, warm latency, peak GPU memory, and offloading on the actual laptop.

For a reliability score, define the harmful-output event first, then calibrate on a held-out development split and report coverage, false acceptance, and failure detection. Rejecting all inputs is not a successful reconstruction method. For whole-face occlusion with inconsistent references, disclose the lack of target evidence; do not turn a similarity score into an identity verification guarantee.

A methods-paper claim requires a clearly differentiated contribution, reproducible gains against close baselines, ablations supporting the mechanism, and final evaluation protected from development choices. A benchmark or negative-result paper needs a valuable protocol and sufficiently strong coverage of the relevant methods. The publication venue must be selected explicitly: IEEE Xplore is the digital library rather than a journal or conference submission destination. None of these steps guarantees acceptance.

## Current artifact boundary

This audit changed no inference code, website behavior, environments, or weights and ran no models. The project already contains a recorded FaceID Portrait SDXL adapter provenance file; that records an existing dependency rather than a new contribution. The local website and reference integration must independently pass real image-generation checks. Earlier single-image results and their limitations remain intact under their original protocol names.
