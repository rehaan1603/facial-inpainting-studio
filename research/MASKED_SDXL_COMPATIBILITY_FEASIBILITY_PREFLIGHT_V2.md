# Compatibility probe v2: isolated attention-backend recovery

10 October 2026. Preserve [v1 architecture/audit/protocol](MASKED_SDXL_COMPATIBILITY_FEASIBILITY_PREFLIGHT_V1.md), code and failed receipt. It completed both neutral full-resolution forwards with maximum difference **0.0**, then failed during backward with `LSE is not correctly aligned (strideH)`. Peak allocation was **7,752,139,776 bytes**. This was not reported as OOM; it does not establish a full training memory limit or useful reconstruction quality.

The exact error string is present in PyTorch 2.11's [memory-efficient attention backward alignment check](https://github.com/pytorch/pytorch/blob/v2.11.0/aten/src/ATen/native/transformers/cuda/mem_eff_attention/kernel_backward.h#L1102). That identifies the rejecting kernel family, not a complete diagnosis of why its saved LSE stride was unsuitable. No framework upgrade, precision change or model change accompanies this recovery.

**Only computational intervention:** run the same v1 direct-UNet/scorer/neutral/backward procedure within `torch.nn.attention.sdpa_kernel([SDPBackend.FLASH_ATTENTION, SDPBackend.MATH])`. This excludes the memory-efficient and cuDNN paths for the entire isolated process scope. Flash handles supported attention; math can handle the differentiable additive bias in fixed 64-query chunks. PyTorch documents this [backend selection context](https://docs.pytorch.org/docs/stable/generated/torch.nn.attention.sdpa_kernel.html). It restores prior flags on exit. The website and installed libraries are not modified.

Keep seed **20261010**, timestep **500**, four synthetic references, the same mask, scales 0.8/0.2, 385 shared parameters, precision, checkpointing, input/target construction, epsilon objective, one disposable optimizer update, and neutral tolerances **1e-3 GPU / 1e-5 CPU**. Preserve failures. Run **1024-equivalent first** into a fresh v2 receipt. A separate **512-equivalent** probe is allowed after failure; record it as lower-resolution feasibility and retain the 1024 failure. No auto-resizing inside one attempt or relaxed tolerance.

The new wrapper also hardens failure reporting: validate/sanitize nonfinite receipt fields, convert a leftover running receipt to an explicit failed status if the original serializer cannot save NaN/Inf, and record wrapper/v1 source hashes plus backend flags before/after restoration. This affects failure receipts only, not tensor operations, gradients or successful numbers. Do not overwrite an existing receipt. Test these failure paths with mocked execution before GPU work.

All v1 limits continue to apply. A pass verifies only one conditional synthetic latent-loss gradient/update with frozen weights. It excludes realistic latents, VAE/image/identity losses, full optimizer history, actual data training and multistep image generation. No checkpoints or application changes. Any later pilot needs its own fully frozen data, objective and schedule. If the v2 probes fail, report the failure and investigate a separately specified memory/gradient architecture rather than claim that the model has been trained.
